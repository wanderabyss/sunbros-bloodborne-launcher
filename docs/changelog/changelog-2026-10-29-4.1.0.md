# 4.1.0 — The new launcher (2026-10-29)

Version `4.1.0+build102926.161820`. Built on 4.0.0.

## Launcher

- Glass design over full-window Bloodborne art (`bloodborne_pc/launcher/qml`): `Theme.qml` and every base control restyled; new `GlassPanel.qml`, `GlassTabBar.qml` and `WorkshopPage.qml`.
- `Main.qml` builds each page on first visit (`Loader`). The window opens in about 0.5 s (was 1.3 s); pages build in 10–220 ms when first opened.
- Backgrounds are pre-blurred JPGs in `launcher/assets/ui/bg/` (1920 wide). Nothing is blurred while the launcher runs. The six `tile-*.png` cards, `launcher-bridge.png` and `setup-workshop.png` (16 MB) were removed.
- Pages: Home, Visuals, Advanced visuals, Online (The Hunter's Dream), Co-op, Dossier, Workshop, Workshop details, Settings and Setup.
- Settings sections (`SETTINGS_SECTIONS` in `bbport_launcher_backend.py`) cover one topic each. Visuals: Display & frame rate became Resolution, Window, HDR and Frame rate; Sharpening left Upscaling; Image effects became Detail and Post-processing. Mods & Patches: Gameplay patches became Gameplay tweaks and Cheats.
- Co-op: the session frame rate is on the Connection step; the Launch step lists the choices.
- "Save settings now" moved to System > Maintenance, "Reduce motion in the launcher" to System > Launch.
- Fix: Home read bbport.ini's "0"/"1" switches as on (HDR and Fullscreen).

### Scaling, Home and polish

- One design, scaled: `Main.qml` lays every page out on a `stage` at 1290 × 830 and magnifies it by `Theme.zoom`: the design fills 80 % of the window, times the A− / A+ step (80–130 %), never below 0.8 or so large that sidebar pages get less than 1040 × 720. The window opens once at 40 % × 45 % of the desktop, centred (about 1460 × 940 on 4K).
- Interface size: `TextSizeControl.qml` (A− / percentage / A+) on Home and in System > Launch; Ctrl + / Ctrl − / Ctrl 0. Saved as `ui_scale` in settings.json (`APP_DEFAULTS`, default `auto`). The live value is `Theme.uiScale`, because `setValue` emits no change signal.
- Popups scale themselves (`GlassComboBox`, Dossier's trophy popup, the shared `ToolTip`): the window overlay is not part of the stage, and binding a scale onto `Overlay.overlay` had no effect.
- Vector icons: `NavIcon.qml` keeps its canvas-style drawing code but runs it on a recorder that emits SVG path data for a `Shape` with `CurveRenderer`, so icons are sharp at any zoom or DPI. The combo box ↕ and Dossier's progress ring are `Shape`s too. New `check` and `alert` icons.
- Home: two columns at the design size, the hero and a side column of Quick settings tiles and a Your hunt card (trophy bar, HD textures, mods); below 1120 px they stack in a `Flickable` with Play at the top. Background `bg/home.jpg` is now `art/hero.png` (moonlit Yharnam) blurred 4 px; cards over bright art use `GlassPanel { smoked: true }`.
- Round glass: `GlassPanel` has no top highlight line by default; tiles, rows, combo boxes and text fields are full pills. The tab bar's highlight slides between tabs; Ctrl+1–7 switch tabs, Esc leaves the advanced Visuals and Workshop pages.
- Audit fixes: `GlassSwitch` has no padding and no gap without a label, so switches end where dropdowns end; Visuals dropdowns are 340 px; presets are one segmented control; Workshop's "Open mods folder" is a glass (not primary) button; `textFaint` is 75 % white; sidebar icon tiles are 30 px with 18 px glyphs (rows stay 40 px so Logs fits at 1290 × 830).
- Co-op: steps are a segmented control with a check on done steps; the flow card fits its content; the account status names what is missing (`CoopSetupPanel.nextNeed`); the backend's co-op status is neutral text, not link-blue.
- First-time setup: the sheet fits the current step (`SetupWizard.neededHeight`) and step status is a check or alert icon, not a dot.

### Updates and release notes

- `UpdateSheet.qml` (on the stage, so it scales): "update" shows the offered release's short changelog, date, download status and Download / Install now / Later; "whatsnew" shows this version's once after an update. Opened from the Home banner ("What's new", was "Details"), Settings > System > Updates, at start for a downloaded update, and at the first start of a new version.
- A downloaded update at start sets `installOffer` (the window reads it when it opens) instead of calling `installUpdate`, which used to show a bare question box before the window. `installUpdate(true)` skips that box when the sheet asked.
- `latest_release()` caches the release body and date; `cached_release_notes()`, `release_notes_section()` (this version's section of the shipped `Release_Notes.md`) and `concise_release_notes()`. The short changelog is a `<!-- launcher: ... -->` block in the release notes (hidden on GitHub, which shows the full notes); without one, the title and each bullet's bold lead-in. `releaseNotesHtml()` renders it with Qt's Markdown reader and readable link colours; "Full release notes on GitHub" opens the release page.
- `last_seen_version` in settings: an update shows what's new once; a first install shows nothing.
- A 404 from the releases API (no release, or a private repository) no longer reports "You have the latest version". Versions read "4.2.0", not the tag "v4.2.0".
- Tests: the next launch offers (does not install), Install now asks once, notes parsing and caching, the short changelog, link handling, what's new after an update vs a first install. Checked end to end against a local stand-in for the releases API: check, background download, offer on the next start, the sheet, the 404 message.
