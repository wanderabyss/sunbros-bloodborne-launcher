# 4.3.3 — Faster repeat starts; DLSS 5 settings now follow your PC (2026-11-06)

Built on 4.3.2.

## DLSS 5 settings

### Why

A player reported the launcher starting with DLSS 5 selected, when it should start clean or choose from the PC. A clean install never does this: the first start's GPU check picks DLSS or FSR 3.1, the display's resolution and a preset, with DLSS 5 off, on every card tried.

Saved settings can, though. They live in `%APPDATA%\bbport-launcher` and survive a new install folder, and finding them skips the first start's check. So DLSS 5 could stay on, or the "DLSS 5 ready" preset stay selected, in a folder without the add-ons or on a card that isn't offered DLSS 5. The game and `run.py` then refused to run it, while the launcher still showed it as chosen.

### What changed

- `bloodborne_pc/launcher/bbport_launcher_win.py`: `dlss5_blocker` says why this PC can't run DLSS 5: the GPU check's "not offered" reason, or files from `DLSS5_FILES` missing from `bin`. A ReShade setup problem isn't a blocker, because the add-ons are in place and the existing warning says what to do.
- `bloodborne_pc/launcher/bbport_launcher_backend.py`: `_settle_dlss5` runs after each start's GPU check. With a blocker, the DLSS 5 switch goes off and the launcher says why. Saved Custom settings change only on a card that isn't offered DLSS 5: `settings.json` is shared between install folders, so a folder without the add-ons leaves them for a folder that has them. A leftover "DLSS 5 ready" preset is replaced by what a first start picks for this card, including the display's resolution. If the GPU check gave no answer, only the switch goes off.
- A PC that can run DLSS 5 keeps the player's choice.
- `tests/test_graphics_presets.py`, `tests/test_depth_workspaces_qml.py`: the blocker's reasons, and the switch and preset with and without the files, on offered and other cards, and with no GPU answer.

### Limits

- "DLSS 5 ready" chosen on an offered card without the add-ons lasts until the next launcher start, then gives way to the suggested preset.
- Without saved Custom settings, a folder without the add-ons also turns the switch off in the shared `settings.json`, so a second folder that has them needs it switched on again.
- The player's report hasn't been matched to their PC or settings, so this fixes the cause found in the code, not one confirmed on their machine.

## Faster repeat starts

### Why

A player reported the game taking an awful time to start from the launcher. A repeat start spent most of its time before the game on work it had already done, and reached the title in about 54 seconds.

### What changed

- `bloodborne_pc/scripts/exit_text.py`, `scripts/prepare.py`: each keeps a stamp and skips its work when nothing changed. A new `eboot.elf` on every start also broke the stamp in `run.py` `shader_prebuild`, so the shader code was extracted again each time; that stamp now holds.
- `bloodborne_pc/scripts/mods.py`, `src/runtime_file.c`: on Windows `build_layer` writes `out/mod-files.txt` (game path, tab, host file) and the game looks paths up in it, in `translate` and in folder listings (`BB_APP0_LAYER`). `/app0` stays the real game folder, and the 28,853-link overlay isn't built.
- `bloodborne_pc/run.py`, `scripts/shader_code.py`, `scripts/patches.py`: Python that reads game files after `mods.py` goes through `mods.game_file`, `game_files` or `layer_file`.
- `tests/test_runtime_file_layer.c`, `tests/test_runtime_file_layer.py` (new), and `tests/test_exit_text.py`, `test_mods.py`, `test_prepare.py`, `test_run_scripts.py`.

### Limits

- First starts are no faster.
- The overlay remains for `run.sh` and for source paths over 250 characters.
- Checked in the game on an RTX 4090 at 2560 x 1440 with DLSS 5, frame generation and 198 mod files: the mods loaded, and it played, saved and exited cleanly. Restarting from inside the game and co-op were not run with the new lookup.

## Tuned preset row

- `bloodborne_pc/launcher/qml/VisualsStudio.qml`: the row names the card the settings were measured on as plain text that follows `launcher.rig`. The white RTX 4090 pill looked like a detected or selected card on every PC.
- `bloodborne_pc/launcher/bbport_launcher_backend.py`, `bbport_launcher_win.py`: a saved `upscaler=dlss` on a card without DLSS stays saved, and the option reads "DLSS (runs as FSR 3.1 on this card)". The game falls back by itself.
- `tests/test_depth_workspaces_qml.py`, `tests/test_graphics_presets.py`.
