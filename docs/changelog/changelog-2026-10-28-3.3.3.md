# Changelog — October 28, 2026

## 3.3.3 — DLSS model per quality mode (DLSS-4) and DLSS 5 kept off

Built on 3.3.2 (HD Texture Pack setup fix, merged from main). Earlier drafts of this work were labelled 3.3.2 on branch `docs/dlss-audit` before main released its own 3.3.2.

- `bbport_dlss.dll` now sends the selected DLSS model only on the active quality mode's render-preset key. Before this, it wrote the model to all six keys, so a manual choice (for example L) applied at Quality too. Auto was already resolved per mode, so its behavior is unchanged.
- `run.py` disables ReShade's Vulkan layer and drops inherited `BB_DLSS5` / `BB_DLSS5_PROBLEM` on every start while the DLSS 5 community bridge is paused. `BB_DLSS5_BRIDGE_TEST=1` (the scripted test only) keeps the layer.
- The in-game DLSS 5 reason no longer points to a missing setup guide. The launcher hint adds the GPU check's "not offered" reason.
- The empty DLSS 5 (route B) hook also covers DLSS's 16-bit output path.
- A missing `nvngx_dlssg.dll` is reported at start (`DLSS: nvngx_dlssg.dll is not beside the game program …`); frame generation still falls back to FSR 3.1.
- Tests: `upscaler-support-test` builds on Windows and re-reads `BB_RENDER_RES` through `Load()`; the QML workspace tests stub the modal "Settings Saved" box that hung `unittest discover`.

- **DLSS bridge ABI 3:** new `NeuralRender*` entry points for DLSS 5, reported unsupported until NVIDIA ships a Vulkan runtime for RTX 40. The packager now requires ABI 3; the renderer still loads ABI 1/2 bridges.
- **DLSS 5 inputs:** the hook after super resolution receives colour, depth, motion, jitter and the camera (near/far/FOV, clip matrices), with optional normals/albedo/mask slots. When the bridge supports it, `dlss5` uses NVIDIA's backend (`DLSS 5: on (NVIDIA)`); no change today.
