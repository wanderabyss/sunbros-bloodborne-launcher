# 4.2.4 — DLSS 4 and DLSS 5 suggestions, and DLSS 5 that says when it can't load (2026-10-30)

Built on 4.2.3. Launcher and `run.py`; no renderer changes.

## Preset suggestions per DLSS generation

- `bbport_launcher_win.py`: `PRESET_TAGS` and `preset_tags(gpu, dlss5_offered)`. Where `recommended_graphics_preset` picks Remastered (GeForce RTX 40 / 50 with 12 GB or more), Remastered is tagged "DLSS 4" and, where the GPU check offers DLSS 5, DLSS 5 ready "DLSS 5". Every other card keeps one plain suggestion.
- `LauncherBackend.presetMarks` (a notifying property, so the buttons follow the GPU check) and `presetSuggestion`; `VisualsStudio.qml` and `SetupWizard.qml` show them (the wizard's two wide buttons grow from 128 to 176 px).
- Measured on an RTX 4090 with the 4.2.3 build: Remastered at 3840 × 2160 held 60 → 120 at about 8.7 ms GPU; DLSS 5 at 2560 × 1440 output held 59-60 at 14-15 ms. 4K with NR upscaling held 60 → 120 only at DLSS Performance (ray tracing Ultra or High), and matched stills were no sharper than 2560 × 1440 output.

## DLSS 5 and ReShade's program list

- ReShade's global Vulkan layer loads only for programs in `C:\ProgramData\ReShade\ReShadeApps.ini`. A 4.2.3 DLSS 5 folder that was never added there ran without the bridge while the game logged "DLSS 5: on (community bridge)".
- `run.py`: `reshade_loads_here` (as the launcher's), and `dlss5_environment` now sets `BB_DLSS5_PROBLEM` instead of `BB_DLSS5_ROUTE_A` when the folder isn't listed, so the game logs "DLSS 5: off - ReShade is not set to load for bin\bb-probe.exe". An unreadable list still lets the route through.
- `dlss5_fps_warning` says the same in the launcher. `dlss5_output_warning`'s NR upscaling text now has the 4.2.4 measurements.
- Tests: `tests/test_run_dlss5.py`, `tests/test_graphics_presets.py`, `tests/test_depth_workspaces_qml.py`.
