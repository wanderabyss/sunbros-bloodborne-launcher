# 4.4.1 — Fixes from the 4.4.0 review (2026-11-06)

Built on 4.4.0.

## What changed

- The later `PipelineCache::WarmUp` was checked and stays, with no change to how it runs. Nothing made between its old and new place reads the shader database, blank frames use only the present scheduler, and the presenter is built before the game's code runs. `tests/test_warm_up_order.py` (new) holds the order. `vk_rasterizer.cpp` only gets a spacing fix.
- `scripts/sojin/save_tool.py`, `run.py`: `backup_folder_name` and `is_backup_folder` sit together in the converter, and `saves_holding` calls `is_backup_folder`. `run.py` used to keep its own copy of the name's pattern. A new test passes folders written by the real `backup()` for all four converters to `saves_holding`.
- `launcher/bbport_character.py`: `get_characters` skips folders that `is_backup_folder` recognises. Its patterns also matched `SPRJ0005 sojin-chikage backup 20261106-204502`, so the launcher listed old copies as characters, and a backup written last could become the profile shown. The rule is loaded from `scripts/sojin/save_tool.py` by file path, because in the packaged launcher `sojin` is the bundled package, which has no `save_tool`. No backup folder is moved or deleted. `tests/test_character_backup_folders.py` (new) holds this.
- `launcher/qml/SettingsWorkspace.qml`: a Save backups row shows its character summary on its own line, which wraps, and the row grows to fit. It used to share one cut-off line with the backup's type, size and file count, which often hid the `(+N)` count. The summary is stored in each zip when it is made, so older backups keep the repeated names they were written with. `tests/test_save_backups_qml.py` holds this.
- `launcher/bbport_launcher_qml.py`: `qt_arguments` adds `-platform windows:fontengine=freetype` only when no platform was chosen. Qt prefers the argument to `QT_QPA_PLATFORM`, so a launcher started with `QT_QPA_PLATFORM=offscreen` still opened a real window, and a `-platform` given on the command line was overridden.
- `tests/test_launcher_build_ahead.py`: the prepare-only check now runs `run.py`'s `main()` with its scripts and the game replaced by records of the calls, instead of comparing positions in the source text. It also checks that a real start converts saves before the game.
