# 4.4.0 — Build ahead, Preparing shaders screen, Stop button, sharper launcher (2026-11-06)

Built on 4.3.5.

## What changed

- `bloodborne_pc/run.py`, `launcher/bbport_launcher_backend.py`, `launcher/qml/HomePage.qml`: build ahead. The launcher runs `run.py` with `BB_PREPARE_ONLY=1` at low priority when its window opens, after settings or mods change, and after the game exits. It stops before saves, online setup and the game. Play during a build keeps it and starts the game when it ends; Stop cancels both. A direct launch does not build ahead. The output is in `build_ahead.log` in the data folder.
- `bloodborne_pc/gpu/shadps4/video_core/renderer_vulkan/vk_presenter.cpp`, `vk_presenter.h`: `Presenter::WarmUpShaders` runs the warm-up as the constructor's last step. If it takes more than 1.5 s, a helper thread presents blank frames at about 60 FPS through the normal present path, so HDR, frame generation and resizing work as for any frame. One blank frame follows, so the screen's last picture does not stay up.
- `vk_rasterizer.cpp`, `vk_pipeline_cache.cpp`: the warm-up moved from the rasterizer's constructor to the presenter's, because the overlay and output passes are made after the rasterizer. Object motion is still set up first.
- `vk_pipeline_serialization.cpp`: reports progress, and on a skip leaves the remaining records stored. They load at the next start, or compile if the game uses them first.
- `bloodborne_pc/gpu/shim/bbport_overlay.cpp`, `bbport_overlay.h`, `window.cpp`: the screen, its input and the controller handling. The game opens controllers only once it runs, so the window thread holds them open while the screen is up. The prompt shows the controller's Options or Menu button, or Esc with none connected. That button, Esc or a click on Skip skips; no other input does. The button's state is read directly, with background input allowed only while the screen is up, because a game started from the launcher may not have the focus. A button held before the screen appeared, or anything in a pad's first half second, does not count. The screen shows "Skipping..." at once, and the log names the input (`Shader screen: skip pressed (controller)`).
- `bloodborne_pc/run.py`: `BB_STARTUP_FONT` chooses the screen's font: the game's own from the prepared maps (`atlas/art/native-font.ttf`), else the launcher's copy (`launcher/assets/ui/bloodborne-font.ttf`). The overlay's embedded face fills in missing characters; the launcher's copy has no percent sign.

- `bloodborne_pc/launcher/qml/HomePage.qml`, `bbport_launcher_backend.py`: a Stop button beside Game running. It needs a second click within 4 s, because it ends the game at once. A Stop is not reported as a failed start.
- `launcher/qml/Main.qml`: automatic zoom stays at exactly 1 below 1.25x, because a small scale softens text without giving it more pixels.
- `bloodborne_pc/tests/test_launcher_stop_and_text.py` (new), `tests/test_home_dashboard_qml.py`.

- `scripts/bake_launcher_art.py` (new), `launcher/assets/ui/bg/*.jpg`, `assets/ui/dither.png`: Home's art was blurred 4 px, 1920 wide and compressed to 119 KB, with colour at half resolution. It is now unblurred and 3344 wide, enlarged 2x from the 1672 px `art/hero.png`, at quality 95 with full colour resolution (1.8 MB). Enlarging adds no detail. The other pages stay blurred, with their JPEG blocks removed.
- `launcher/qml/GlassPanel.qml`, `Main.qml`, `Theme.qml`, `HomePage.qml`, `GlassTabBar.qml`: `frost` blurs what is behind Home's top-level panels, live at half resolution, so the art stays sharp elsewhere. Nested panels skip it. A very faint dither over the window hides 8-bit banding in the dark shades and glass gradients.
- `launcher/bbport_launcher_qml.py`, `launcher/assets/fonts/`, `qml/Theme.qml`: the launcher's text is now IBM Plex Sans, hinted (SIL Open Font License), bundled. It uses native text through the FreeType engine at zoom 1, hinted to the pixel grid and without ClearType's colour fringes, and curve text when the window is enlarged, because native text blurs when scaled.

- `vk_pipeline_serialization.cpp`, `vk_presenter.cpp`: the Preparing shaders screen shows only for real preparation: no usable driver cache, another shader profile, or over 300 shaders to translate. Every start reloads its pipelines and translates about a hundred shaders; that took 3.5 to 16 s with DLSS 5 on here, and it now shows Starting the game.
- `gpu/shim/bbport_overlay.cpp`, `vk_presenter.cpp`, `vk_temporal_upscaler.cpp`: from the warm-up until the first UI frame, black with "Starting the game" covers the game's first frames, which show its grey clear colour. A 30 s limit covers a start with no UI frame.
- `bloodborne_pc/scripts/enhancements.py`: each file set's line in the log gives its time, for example `Enhancements: Lamps: Level Up and Storage (16 files) took 12.3 s`.
- `bloodborne_pc/run.py`, `tests/test_weapon_off_saves.py` (new): with a weapon switch off, starts no longer convert the converters' own backups. This bug dates from 4.2.15. `sojin_saves` searched every folder beside the save, so each start converted a backup, which made a backup of that backup, still holding the weapon. One PC reached 89 save folders (208 MB at 77), 39 save tool runs in one start and 31.3 s from Play to the game process. Backups now stay as they are. Folders from earlier versions are not removed, because some hold the only unconverted copy of a weapon.

## Checks

- First start: screenshots show the screen with the game's font and a moving bar, on a display with Windows HDR on. The game goes on to the logos.
- Build ahead, real scripts and game: no save folder is made by the build; Play during a build starts the game after it (214 s from Play on an empty folder); Stop during a queued Play starts no game and reports it as stopped. A Stop starts a new low-priority build, so the files still get finished.
- Esc: the log reports the skip, the game goes on to the logos, and the next start prepares the rest.
- Launcher renders on the GPU at 1477x950 (this PC's window, 100% Windows scaling), 2800x1700 and 200%: frost stays aligned, and text and edges are clean. These are screenshots, not a judgement of how it looks on an HDR panel.
- **Limit:** the launcher is 8-bit SDR like other desktop apps. PC apps cannot output Dolby Vision, and this does not add HDR.
- Repeat starts with DLSS 5, frame generation and HDR10 on, from the packaged launcher: the logs show no shader screen, no crash or device loss, and a clean exit to desktop.
- Weapon switches off, on a temporary copy of a save and six backups, three passes of the real `sojin_saves`: one conversion and one new backup on the first pass, none after. Save tool runs that exit 1 are `backup()` refusing a folder name over the 255-character limit, which changes nothing.
- **Not checked:** a press of a real controller button or a click on Skip since the button changed, the shader screen with HDR output, in fullscreen or in exclusive fullscreen, a slower PC, and a full game start with this fix.
