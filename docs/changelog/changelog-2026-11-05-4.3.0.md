# 4.3.0 — Spatial sound: the game's 7.1 mix reaches Dolby Atmos, Windows Sonic and DTS (2026-11-05)

## Why

Bloodborne has no Dolby code of its own (no Dolby, Atmos, AC-3 or bitstream strings in its executable), but it does mix 7.1. A 130 s capture of the main audio port had a separate signal in all eight channels: fitting C, LFE, the sides and the rears from L and R removed under 3 dB.

With Dolby Atmos for Headphones on, Windows still reports 2 channels for the output. So the port folded the mix to stereo first, and Atmos only ever processed that stereo. A rare crash also ended in a heap panic that doesn't say which memory block it rejected, and paper white stopped at 400 nits.

## What changed

**Spatial sound** (`bloodborne_pc/src/runtime_audio_spatial.c`, `spatial_ring.h`, `runtime_audio.c`)
- With a spatial sound format on for the default output, the main port's 8 channels go to eight static spatial audio objects (`ISpatialAudioClient`), so the format renders each from its speaker position.
- With spatial sound off, nothing changes: stereo stays stereo, and a 5.1 or 7.1 output gets its channels through SDL as before.
- Windows pulls audio on its own thread. A queue between that thread and the game keeps a 40 ms lead and absorbs clock drift.
- If the stream ends because the output changed, the port returns to SDL for the rest of the run.
- `BB_AUDIO_SPATIAL=0` turns it off. `last_run.log` says `Runtime: spatial sound: on`.
- The music port stays on SDL. It wrote nothing in the capture.

**Crash logging** (`bloodborne_pc/src/heap_trace.c`, `probe.c`)
- When the game's heap rejects a free ("given memory block seems to be improper or freed already"), `last_run.log` gets `Heap trace:` lines: the block, its header and neighbours, its heap, the surface, and any earlier free of it among the last 256 GPU memory frees.
- The same report runs for a fault inside the heap's free, which a damaged block header causes instead of a panic.
- Fault reports also print r8-r15. `BB_HEAP_TRACE=0` turns the trace off.
- The hooks on the panic paths never run in a healthy game. The GPU memory free's hook adds one ring entry per free.

**Audio capture** (`bloodborne_pc/src/runtime_audio.c`)
- `BB_AUDIO_DUMP_GUEST=<path>` saves the game's PCM before any volume or downmix, every channel. `BB_AUDIO_DUMP` still writes after the downmix, which is 2 channels on a stereo output.

**HDR paper white** (`bloodborne_pc/gpu/shim/bbport_settings.h`, `launcher/bbport_launcher_win.py`)
- Up to 800 nits, from 400. 500, 600 and 800 are new options. Higher values brighten midtones and leave less range for highlights below the peak.

## Tests

- `tests/test_spatial_ring.c`: channels stay apart, playback waits for the lead, an empty queue gives silence, one underrun and a new wait, and a long queue drops its oldest frames.
- `tests/test_heap_trace.c`: a block freed twice is called a double free, a block seen once is not, the report runs once, and only faults inside the free report.
- `tests/test_launcher_hdr_levels.py`: hand-edited paper white snaps to the new options.

## Checked in the game

On a 4090 with wired headphones and Dolby Atmos for Headphones: `8 ch -> 8 ch`, about 2 minutes of scripted play with no underruns or drops, and the sound checked by ear. Paper white 600 and 800 were compared in game with DLSS 5 on.

Not yet run: real 5.1/7.1 speakers, Windows Sonic, DTS, the return to SDL after an output change, NG+7 alongside these changes, boss music in the capture, and a heap panic in the real game.
