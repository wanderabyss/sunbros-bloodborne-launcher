# Changelog — October 28, 2026

## 3.4.0 — DLSS roadmap: GPU time, a "DLSS 5 ready" preset, DLSS through Streamline

Built on 3.3.3. Native DLSS 5 still waits for NVIDIA.

### GPU time (A5)

- **Render targets read back as buffers (A5.1).** Each frame, Bloodborne's guest copy shader `3d5ebf4e` reads four 2560×1440 render targets as buffers: an RGBA16F target, two RGBA8 targets and the D32S8 depth.
  - **Before:** each image was copied into a linear staging buffer, then tiled into game memory by a second pass.
  - **Now:** `TileManager::TileImageDirect` tiles each one straight from the image in one compute pass. Colour is read as `r32ui`/`rg32ui`; depth is sampled.
  - **A/B:** toggle bit 60 (`DirectImageTiling`) brings back the old path.
- **DLSS sharpening (A5.2).**
  - **Before:** sharpening is on by default (0.50). DLSS wrote the UI image, the sharpen pass copied it to an RGBA32F image and sharpened it back in place, and a blit followed.
  - **Now:** DLSS and FSR 4 write their 16-bit output, and one pass sharpens it straight into the UI image.
  - **A/B:** toggle bit 59 (`FusedSharpenCopy`) brings back the old path.
- **Ultra ray tracing (A5.3).** No change. RTG-3 was already done (checkerboard moon shadows). With RT Ultra the G-buffer costs 1.42 ms against 1.43 ms with RT Off, so the rest of RTG-2 has nothing left to save.

### Presets (A6)

- **"DLSS 5 ready" preset:** 2560 × 1440 output, DLSS Quality, ray tracing Low, Reflex, and DLSS 2× frame generation at a fixed 60 FPS.
  - It appears only when the graphics-card check says the card is offered DLSS 5.
  - It leaves `dlss5` as set.
- **60 FPS warning:** the frame-rate and DLSS 5 rows warn when a DLSS 5 request is saved at any rate other than 60 FPS. In game, the menu already said the same.

### DLSS through NVIDIA Streamline (A1, experimental)

- **What it is:** `gpu/dlss_bridge_sl` builds `bbport_dlss_sl.dll`, which offers the same bridge interface (ABI 3) on Streamline 2.14.16 in manual-hooking mode.
- **How to use it:** it ships in `bin\streamline` with NVIDIA's signed runtime and is chosen with `BB_DLSS_BACKEND=streamline`.
  - The renderer then routes present, swapchain and device-wait calls through Streamline's proxies.
  - NGX stays the default.
- **What it covers:** Super Resolution with the same per-mode model rule.
  - **Frame generation:** this backend doesn't offer it, because Streamline's DLSS-G would take over presentation. The renderer uses FSR 3.1 frame generation instead.
  - **Reflex:** stays on the port's own `VK_NV_low_latency2` path.
  - **DLSS 5:** Streamline reports `kFeatureDLSS_NR` unsupported (2.14.16 ships no plugin for it).
- **Building it:** `build_dlss.sh` builds it when `STREAMLINE_SDK_ROOT` is set, and `package.sh` checks it and ships it.

### HDR input for DLSS (A4)

Measured, not changed. Live resolution already gives DLSS the linear HDR scene colour. At the same DLSS Quality and 4K output, its picture was visibly softer than the default path, which gives DLSS the tonemapped frame. The default stays as it is. DLSS 5 will get tonemapped colour in the default path.

### Shader-compile hitches

- **The problem:** a new graphics pipeline was built on the GPU thread, and NVIDIA's driver takes up to ~120 ms for one it has never seen. The first boss run's worst frames (Shadows of Yharnam 100.5 ms, Amygdala 116.9 ms, Orphan of Kos 116.6 ms) were these compiles.
- **Bigger catalog:** `shader_catalog/nvidia` gained 300 records (2,253 in total) from a boss run and a play cache.
  - A first start pre-builds 741 pipelines instead of 665 (11.2 s instead of 9.2 s on an empty driver cache).
  - The same boss fights then had 0 compiles and worst frames of 18–34 ms.
- **Background builds** (`PipelineCache::QueueBackgroundPipeline`, toggle bit 61 `AsyncEffectPipelines`):
  - **What:** a new pipeline for an effect (blended, no depth writes) or an object (a G-buffer draw, or a depth-tested triangle mesh writing a depth buffer earlier draws used) is built on one of two worker threads.
  - **Meanwhile:** its draws are left out until it's ready.
  - **Safety:** the worker reads the draw's resource descriptors from copies of its user data.
  - **Not backgrounded:** full-screen passes and depth buffers no draw has used yet.
  - **Worst case** (pre-build off, NVIDIA cache redirected to an empty folder): Cathedral Ward's compile time in frames went from 1,481 to 60 ms and its worst frame from 250 to 18 ms, and no area had a frame over 40 ms.
- **Diagnostics:**
  - `BB_GPU_PROFILE` prints frames over `BB_GPU_PROFILE_SLOW_MS` (40 ms by default) with their largest segments.
  - Ray tracing prints heavy frames.
  - With `BB_FPS_LOG`, compile lines name the kind of pipeline, and `BB_PIPELINE_DEBUG=1` describes each one built on the GPU thread.
- **Harness:** `ingame-session.ps1` has a `pad` step (any buttons and sticks) and a `-Toggles` option (toggles from the first frame), and retries its mark-file writes.

### Smaller changes

- `BB_DLSS5` is only the `dlss5` setting's override. The community bridge's "set up" signal is now `BB_DLSS5_ROUTE_A=1`, which `run.py` still drops while that route is paused.
- If a presentation frame's allocation fails (not out of memory), it is retried once after the GPU is idle.
