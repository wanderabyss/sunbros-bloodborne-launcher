# Changelog — October 27, 2026

## 3.3.1 — Remastered, title presentation and graphics availability

- Remastered explicitly selects DLSS Quality, automatic DLSS model, Ultra ray tracing, object motion, highest model detail, 16x anisotropic filtering, screen-space reflections, AO strength 100%, Reflex and DLSS 2× frame generation. An installed HD pack is enabled even when ordinary mods are disabled.
- Reapplying Remastered clears only advanced BB_FPS, BB_FPS_LIMIT and BB_VBLANK_HZ assignments and the manual frame cap. Output resolution, cosmetic preferences and unrelated variables are preserved.
- Home distinguishes base FPS from output targets, supports the selected generation multiplier and exposes advanced FPS overrides. A supplied gameplay run confirms 60 base / 120 accepted-image FPS with increasing DLSS generated counts.
- Generated title movie copies uniformly zoom only the padded backgrounds on 16:9 output. A small top/bottom crop removes baked side padding; commands, ActionScript, original assets and player-mod precedence remain intact. BB_TITLE_FILL=0 restores original framing. Other aspect ratios keep existing title framing.
- Native movie-only bitmap sampling uses linear filtering before a 3D scene depth is available. It reduces pixel steps without inventing missing source detail; gameplay and depth samplers retain their filtering. Visual confirmation remains pending.
- Extra injected PC System sections default off; PC controls remain in the launcher. BB_PC_MENU=1 explicitly restores the old menu.
- DLSS5, dynamic secondary lights and ray-traced water reflections show unavailable controls. Stored On requests are preserved for compatibility and do not indicate active effects. See implementation requirements.
- Downloaded updates restore without a release cache, retain ready notices, and offer confirmed installation on startup when background downloads are enabled. Home provides update actions.
- Packaging clears only the selected staging folder. Version metadata advances to 3.3.1. Delivery uses the canonical bbport-windows-3.3.1.zip filename.

### In-game desktop exit and documentation follow-up

- Confirming the in-game Exit Game hides the game window, preserves its original save/return action, and requests normal desktop shutdown when the title menu is reached. No forced process termination or save timeout is used. Canceling does not hide or quit. `BB_EXIT_TO_DESKTOP=0` keeps the original visible return-to-title behavior.
- The native Exit confirmation pointer and title call are checked before patching. A mismatch leaves that hook unavailable and logs the reason. This path is independent of the optional PC menus and the separately installed title-menu Exit XML.
- User confirms the separate title-menu Exit Game works. The new hidden save-then-exit flow still needs in-game verification.
- README now shows current full-width launcher screenshots with example profile data, and the changelog index exposes 3.3.1 directly.

### Exit wording and package refresh

- Generated message archives now say **Exit to desktop**, **Save your progress and exit to desktop.**, and **Save your progress and exit to desktop?** The original game archives remain unchanged. The wording follows the desktop-exit opt-out and does not add PC menu sections.
- The user confirmed the hidden in-game exit works. Its previous return-to-title wording is replaced in the new package.
- Windows build extraction completes in a temporary folder before the playable package is swapped into place, with rollback on swap failure and settings/save preservation. This avoids opening an EXE while its Qt/Shiboken files are still extracting, which can trigger the classic Tk fallback. Its background is bundled launcher/art/hero.png, not a cached screenshot.
