# 4.2.6 — Seamless co-op hosting: the co-op server ships again (2026-10-31)

Built on 4.2.5. Packaging only; no game, renderer or launcher code changes.

## Why

A 4.2.5 host rang a guest's sign over Tailscale and the guest never arrived: BBSC's timeline showed `HTTP: ringing the sign of user …` about once a minute for seven minutes, then `lua event: OnRoomTimeOut`. The guest was signed in to the host's game server and connected to the relay the whole time.

The 4.2.5 package had no `bin\coop-server`. `launcher/bbport_coop.py` (`bundled_server`) looks for `bin\coop-server\shadnet.exe` and, without it, runs BBSC's own `shadnet.exe`, which drops the P2P signaling this port's network code sends (the STUN framing `packaging/windows/shadnet-p2p/*.patch` fixes). `package.sh` only copied `out/coop-server` when it had been built and otherwise printed a warning, and `scripts/build_dist.py` built it only with `--build-coop`, so the package went out without it.

## What changed

- `packaging/windows/package.sh`: a missing `out/coop-server/shadnet.exe` stops packaging with an error, unless `BB_PACKAGE_NO_COOP_SERVER=1`.
- `scripts/build_dist.py`: builds the co-op server whenever `out/coop-server/shadnet.exe` is missing (`--build-coop` still forces a rebuild), and refuses a stage without `bin/coop-server/shadnet.exe` (`coop_server_missing`) before zipping. That also covers `--only-zip` on an old stage, and `package.sh` failures, which the wrapper only reports as a warning.
- `build.md`: the co-op server is required, not optional.
- Tests: `tests/test_build_dist_coop.py` (a stage with and without the server, the opt-out, and that `package.sh` stops).

## Hosts upgrading from 4.2.5

The launcher runs this port's server from `%LOCALAPPDATA%\bbport-coop\shadnet-bbport`, with its own `db` and `shadnet.cfg` (the registration key in invites). Accounts made while hosting on 4.2.5 are in `BBSC-0.0.2-Server\server\db`. To keep them, copy that `db` folder and its `shadnet.cfg` into `shadnet-bbport` while the launcher is closed.
