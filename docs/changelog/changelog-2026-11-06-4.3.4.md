# 4.3.4 — Start timing in the log; test fixes; in-game restart and co-op checked (2026-11-06)

Built on 4.3.3.

## Checks

- **Restart from inside the game:** an RTX 4090 at 3840 x 2160 output, with mods on. A setting was changed and "Apply and restart" pressed in the guide. The log shows `Runtime: restarting through run.py`, then `Runtime: 77 files over the game` again, and the game returned to gameplay with the setting saved. No errors.
- **Co-op:** two clients on the same PC through `bbsc-launch.exe`, with mods on, against BBSC's servers on `127.0.0.1`. Each loaded the 77 mod files, BBSC verified its patches and readied its kit, both registered with the relay, and both reached gameplay.
- **Start timing:** a normal start on an RTX 4090 at 2560 x 1440 output with DLSS 5, Native HDR and 198 mod files. It was the first start after a rebuild: 10.5 s of preparation, game process at 11.4 s, first UI frame at 35.0 s. The shader step ran for 4.4 s and the pre-build took 16.4 s, which a repeat start should not repeat. It held 120 FPS, then saved and exited cleanly. A repeat start on this build has not been timed.
- **Not checked:** a summon between two players, co-op between two PCs, and any AMD or Intel card. The tuned preset row and the DLSS text on such cards are covered only by simulated GPU names.

## What changed

- `bloodborne_pc/launcher/bbport_launcher_backend.py`: `play` sets `BB_START_TIME` when Play is pressed.
- `bloodborne_pc/run.py`: `StartTiming` logs `Start timing: <step> took N s, at N s` for each step before the game starts, and for removing a temporary mod view at exit. A restart from inside the game counts from its own start.
- `bloodborne_pc/gpu/shim/bbport_start_timing.h` (new), `src/probe.c`, `vk_temporal_upscaler.cpp`, `vk_camera_motion.cpp`: the game process start, first UI frame and first gameplay frame. The gameplay time includes time on the menus.
- `bloodborne_pc/tests/paths.py`: `real_bash` and `with_bash_first`. On Windows `bash` on PATH is usually the WSL stub, which runs the script in Linux without the test's environment. The tests now use MSYS2's or Git's Bash, and skip when neither is there.
- `tests/test_run_settings.py`, `test_mods.py`, `test_build_dist_coop.py`: use them.
- `tests/test_build_dist_swap.py`: no `pytest` import, so test discovery works without pytest.
- `tests/test_gpu_runtime_stubs.cpp`, `gpu/CMakeLists.txt`: the stubs and the `onecore` library `camera-motion-test`, `scene-resolution-test` and `taa-shader-test` need to link on Windows.

## Test results

- Python: every test passes or skips. The skips need a game folder, a prepared game image, Linux or Developer Mode.
- Native: 38 of the 41 CMake `*-test` targets pass.

## Limits

- `camera-motion-test`, `scene-resolution-test` and `taa-shader-test` link but crash on Windows, in Vulkan-Hpp's dispatcher setup during `Vulkan::CreateInstance`, before any test code runs. Matching `vk_platform.cpp`'s `VK_USE_PLATFORM_WIN32_KHR` in those tests didn't fix it, and the cause isn't known. The game itself starts Vulkan normally.
- `build.sh --test` is Linux-only: its Windows branch exits first, so its native tests didn't run here.
